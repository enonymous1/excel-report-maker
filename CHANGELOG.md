# Changelog

## 2.0.0 — 2026-10-27

Sanitized public export and modernization of the former `mp-excelMaker`.
The earlier private history is intentionally not included; this is a
fresh single-commit export. All sample people, emails, and scores in
this repository are fictional, and the real proposal data that v1 had
committed under `local_configs/`, `local_data/`, and `outputs/` is
not present in any form.

### Added

- Installable package (`excel_report_maker`) with the `excel-report-maker`
  CLI: `generate`, `validate`, and `list-templates`. Templates bundled
  with the package resolve by name with no checkout required.
- Template and data validation with named errors (`TemplateError` /
  `DataError`): wrong row lengths, unknown report types, unknown format
  names, and bad sheet names fail before any file is written.
- pytest suite that generates real workbooks and reads them back with
  openpyxl, covering both generators, the master reference config, the
  CLI, and every fixed v1 bug below.
- GitHub Actions CI (Python 3.11–3.13): ruff, ruff format, mypy, pytest.
- MIT LICENSE, `.gitattributes` (LF normalization), and a `.gitignore`
  that actually ignores `outputs/`, `local_configs/`, and `local_data/`.

### Fixed

- **Advanced Builder was unreachable.** The sidebar value was
  `🚀 Advanced Builder` but the branch compared against
  `Advanced Builder`, so the main template/data workflow rendered
  nothing. The UI now branches on shared mode constants.
- **Master reference config produced no conditional formatting.**
  `_comment` keys inside rules were passed to XlsxWriter, which
  silently dropped each rule, and the `alert_red` format name had no
  definition and would have crashed without that mask. `_`-prefixed
  keys are now stripped, format names resolve through the template's
  `styles` registry and built-ins, and unknown rule options are errors.
- **Ignored template features now work:** explicit column `width`,
  `page_setup` (orientation, paper size, margins), and the `styles`
  registry are all honored by the engine.
- **Empty and ragged data crashed.** An empty checklist raised a NaN
  conversion error and a short row crashed inside a DataFrame
  constructor. Empty checklists now produce a header-only workbook;
  ragged rows and missing payloads raise `DataError` naming the row.
- **Hardcoded matrix layout.** The score column (was column 5) is now
  the template's `score_column`, and the width cap (was column 6 at
  100) is the template's `width_cap`.
- **Download buttons nested inside Generate buttons** disappeared on
  the rerun triggered by clicking them. Generated bytes are now kept
  in session state and the download button renders independently.
- **Stale manual-JSON state** in the Advanced Builder suppressed parse
  errors for typed input. Pasted JSON is parsed directly on every run
  and invalid input is shown as an error.
- **Template Architect** swallowed preview errors with a bare
  `except: pass`, crashed its preview for matrix templates, and saved
  under an unsanitized user-supplied name. Filenames are now
  sanitized (no directories or traversal), drafts are validated, and
  matrix previews use a proper section payload.
- **Basename collisions** in template/data pickers: two files with the
  same name in different directories overwrote each other. Options are
  keyed by relative path.
- **Docs contradicted the repo:** the README claimed `local_configs/`,
  `local_data/`, and `outputs/` were gitignored while all three were
  tracked. The ignore rules now match the docs.

### Changed

- The engine no longer routes checklist data through pandas; it writes
  with XlsxWriter directly. pandas is no longer a dependency.
- Templates were renamed to neutral names (`staff_checklist`,
  `compliance_checklist`, `evaluation_matrix`,
  `evaluation_scorecard`); the former `world_bank_*` templates are the
  compliance/scorecard templates with generic file names.
- `PROJECT_STRUCTURE.md` was folded into the README.
- Line endings normalized to LF; requirements moved into
  `pyproject.toml` with pinned minimum versions (XlsxWriter, json5;
  Streamlit as the `ui` extra).

### Verified here

- Engine, config, and CLI: 30 pytest tests, ruff, and mypy, all green
  from a fresh install (see the delivery notes for the exact gates).
- Streamlit UI: rendered headlessly with Streamlit's `AppTest` — all
  four modes load with no exceptions, and switching the sidebar radio
  to Advanced Builder reaches the Advanced Builder page (the v1 dead
  branch). A headless `streamlit run app.py` server also answered
  HTTP 200 with no tracebacks. A real-browser click-through,
  including the download buttons, remains a Windows-side check after
  push.
